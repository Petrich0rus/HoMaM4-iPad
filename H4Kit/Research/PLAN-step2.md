Envelope: the program envelope of PLAN-step1.md applies (repos, no game material in git, fidelity + [I] marking, logic in H4Kit, touch mapping, stops S1–S5, one verified commit per slice pushed, rollback = git revert), with ONE amendment: the device performance check (60 fps / < 1 GB) that PLAN-step1 scheduled "at the latest the first slice of step 2" is re-assigned to slice 7d (first slice that runs the app), acceptance P5; if no device is available then, it is reported as not verified and stays owned by 7d's successor.
Dependencies: 7a → 7b → 7c → 7d-L → 7d-A (7b's passability uses the resolved objects of 7a: concrete footprints and random monsters turned into blocking armies; 7b's reference input is the frozen 7a reference output; 7c and 7d use H4Game from 7a).

Outcome of step 2 (7d split into 7d-L logic + 7d-A screen): open a map → "New game" (difficulty choice) → the map shows the started game (random objects replaced by real towns/creatures/artifacts/resources, armies and heroes as animated sprites, owner flags) → tap a hero to select it, tap a destination to see the path (arrows coloured by day), tap again to walk (animated), movement points per day, End turn (new day), walking onto a resource pile / artifact / treasure-like pickup collects it. Single human player at a time (hot-seat order of human players), no AI turns (other players skip), no combat (hostile armies block the path; entering them is refused with a message), no town screen, no fog of war (whole map visible; shroud rules not decoded).
